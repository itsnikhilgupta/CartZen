# CartZen Machine-Learning Recommendation Service

Independently deployable Python/FastAPI microservice providing interpretable ML recommendations for CartZen scan-and-go supermarket shoppers.

---

## 🏗️ Architecture Overview

The ML recommendation service functions as an advisory intelligence layer decoupled from CartZen's core transaction systems.

```
Next.js Web Application
        │
        ▼
Recommendation API (`RecommendationService`)
        │
   ┌────┴──────────────────────────┐
   ▼ (Primary - 500ms Timeout)      ▼ (Automatic Fallback)
RecommendationEngineML      RecommendationEngineV1 (Rules/Bestsellers)
   │
   ▼ (HTTP POST /recommend)
Python FastAPI Service (`ml-service`)
   │
   ▼
Interpretable ML Model (TF-IDF + Cosine Similarity)
```

---

## 🔒 Privacy & Feature Engineering

Features are strictly privacy-conscious and exclude sensitive personal attributes (race, religion, health diagnoses, political views).

### Feature Set:
1. **Purchase Frequency**: Historical purchase count per candidate product.
2. **Recency**: Elapsed time since last customer purchase/interaction.
3. **Category Affinity**: Frequency weights derived from category interaction vectors.
4. **Product Content Similarity**: TF-IDF vector representations of product brand, category, and non-sensitive nutrition characteristics.
5. **Nutrition Characteristics**: Non-sensitive classification tags (`HIGH_PROTEIN`, `LOW_SUGAR`, `HIGH_FIBRE`, `LOW_CALORIE`).
6. **Price Preference**: Variance between user preferred spend tier and candidate price.
7. **Recommendation Interaction History**: Customer clicks and add-to-cart signals on previous recommendations.
8. **Repeat Purchases**: Re-order affinity signals.

### Data Leakage Guard:
The feature extraction pipeline (`app/features.py`) accepts a `cutoff_timestamp` parameter. Features are evaluated **strictly prior** to the target evaluation date during offline training and validation, ensuring future purchase data never leaks into historical feature matrices.

## 🤖 Interpretable Model Design

To maintain high inference speed (<50ms), full explainability, and operational simplicity, the system utilizes a **Content-Based Similarity Matrix + TF-IDF Vectorizer & Cosine Similarity**.

- **Model Versioning**: `v2.0.0-ml-content-cosine`
- **Explainability**: Every recommendation includes a human-readable, data-grounded rationale (e.g., *"High protein option matching your preference"*).

---

## 📊 Performance Metrics & Offline Evaluation

Model quality is evaluated via `app/evaluator.py`:
- **Precision@K**: Proportion of recommended items in top $K$ that user purchased.
- **Recall@K**: Proportion of total user purchases captured within top $K$.
- **NDCG@K**: Normalized Discounted Cumulative Gain accounting for rank ordering.
- **CTR (%)**: Click-Through Rate on recommended items.
- **Add-To-Cart Rate (%)**: Conversion from recommendation view to cart addition.
- **Purchase Conversion Rate (%)**: Final purchase completion rate.

## 🚀 Deployment & Operational Fallback

### Running the Python Service

```bash
# Install dependencies
pip install -r requirements.txt

# Run server with Uvicorn
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### Docker Deployment

```bash
docker build -t cartzen-ml-service .
docker run -p 8000:8000 cartzen-ml-service
```

### Resilient Fallback Guarantee
- Next.js calls `ml-service` via `RecommendationEngineML` using a **500ms strict timeout** (`AbortSignal.timeout(500)`).
- If `ml-service` is offline, unreachable, or timing out, `RecommendationEngineML` automatically catches the error and returns recommendations generated by `RecommendationEngineV1`.
- The ML service **NEVER** blocks checkout, payment processing, barcode scanning, or e-bill receipt generation.
